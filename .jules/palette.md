## 2024-10-12 - [Accessibility Tree Override via Fallback aria-labels]
**Learning:** Adding an automated fallback `aria-label` to reusable UI components (e.g., using a tooltip `title` as `aria-label`) causes the screen reader to prioritize the `aria-label` over the visible child text. This will override the button's accessible name and break Testing Library queries (e.g., `getByRole('button', { name: "Text" })`).
**Action:** When creating fallback accessibility logic for components like `Button`, always ensure it only applies to icon-only elements (e.g., conditionally verifying `!children` before assigning `aria-label`).
## 2024-05-01 - [ARIA labels in reusable components]
**Learning:** Checking for truthiness of children (like `!children`) is an unreliable way to detect if a component is icon-only in React, since React elements like `<Icon />` evaluate to truthy objects. This breaks ARIA label fallback logic where `title` should be used for `aria-label` when no text is provided inside the component.
**Action:** Use `React.Children.toArray(children).every(child => typeof child !== 'string' && typeof child !== 'number')` to correctly identify if a component lacks text content, ensuring that automated `aria-label` logic applies correctly to icon-only components without breaking tests that query by role/name.
