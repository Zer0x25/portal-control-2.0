# .hermes.md — portal-control

Portal de control interno (Server.lab). Stack: gateway (nginx custom) -> frontend (React/Vite) -> backend (Node/Prisma) -> db (Postgres) + pgbouncer.

## Paths
- Repo: /home/zrx1/server.lab/repos/portal-control
- Manifiestos: `compose.yaml` (prod/GHCR) y `compose.dev.yaml` (dev)

## Servicios / puertos
- `portal-control-backend-1`  :4000
- frontend / gateway / db / pgbouncer en red `proxy_net`

## Despliegue GitOps (NO build local en prod)
- GitHub Actions construye y publica imágenes en `ghcr.io/zer0x25/portal-control-*` (gateway, frontend, backend).
- Portainer despliega el stack desde esas imágenes prebuild (NO usa `build:` en server).
- Variables de entorno se gestionan en **Portainer (Stacks -> Environment Variables)**, no en `.env` físico.
- Flujo: cambiar código -> push a GitHub -> runner build + Portainer pull.
- Para forzar redeploy: Portainer -> stack -> "Update" / Pull image.

## Comandos útiles (solo inspección)
```bash
docker ps --filter name=portal-control
docker logs -f --tail=100 portal-control-backend-1
docker compose -f compose.yaml config     # validar manifiesto
```

## Notas
- Public link: https://portal.tu-dominio.com (Caddy -> gateway).
- NO ejecutar `docker compose up --build` localmente para prod; usar el pipeline GHCR + Portainer.
- `compose.dev.yaml` sí usa `build:` para entorno de desarrollo local.
